# Данные профтестов

## Тесты на сайте

Один тест = один JSON-файл в этой папке. Загрузка: `python manage.py load_tests`.
Образцы формата лежат в `examples/` (их команда не загружает):
`personality_example.json` и `knowledge_example.json`.

Поле `kind` задаёт вид теста:

| kind | Вид | Пример |
|---|---|---|
| `career` (по умолчанию) | профориентационный | ДДО Климова (`klimov_ddo.json`) |
| `personality` | личностные качества | опросник с ответами «от 1 до 5» |
| `knowledge` | знание предмета ЕГЭ | задания с одним правильным ответом |

Основа формата у всех одна: шкалы с расшифровками и вопросы, у каждого варианта ответа
есть шкала и баллы. Чтобы не повторять одно и то же, есть сокращения:

- **Шкала ответов на весь тест** (`answer_scale`): варианты «Совсем не согласен … Полностью
  согласен» с баллами задаются один раз. Вопросу достаточно указать `"scale"`.
  `"reverse": true` переворачивает баллы для обратных утверждений
  («Я часто откладываю дела» для шкалы «Организованность»).
- **Правильный ответ** (`"correct": true`): правильный вариант даёт 1 балл, остальные 0.
  В тесте на знания у каждого вопроса ровно один правильный ответ.
  Шкала здесь — тема (алгебра, геометрия), а `"subject"` у шкалы — предмет ЕГЭ
  (`math`, `russian`, `physics` и т. д.).
- Вариант без `"scale"` берёт шкалу вопроса.

`"is_active": false` — тест загружается, но на сайте не показывается.

Расшифровки шкалы должны покрывать все баллы от 0 до максимума подряд.
Тексты вопросов и расшифровок берём из методики и указываем её в `"source"`;
сами их не придумываем.

## Связь с направлениями обучения

`directions/<код теста>.json` — какие направления подходят к каким шкалам
(например, тип «Человек — знаковая система» → группы 01, 09, 38…).

## Результаты из центра профориентации

Таблицу центра (CSV или Excel) загружаем командой:

```
python manage.py import_external <файл соответствия> <таблица>          # проверка, ничего не пишет
python manage.py import_external <файл соответствия> <таблица> --save   # запись в базу
```

Файл соответствия `external/<источник>.json` говорит, какой столбец таблицы что означает.
Образец: `external/example-center.json`. Под каждую новую таблицу пишется свой файл,
код при этом менять не нужно.

- `participant_code_column` — столбец с кодом участника нашего сайта (P-XXXXXX).
  Ученик сообщает код центру; новых участников импорт не создаёт.
- `date_column`, `date_format` — дата прохождения (необязательно).
- `tests` — тесты из таблицы, у каждого шкалы: `column` (столбец), `name` (как показать),
  `max`, и уровень: либо таблица `levels`, либо столбец `level_column`.

Читаются **только** перечисленные столбцы. ФИО, телефоны, школы и прочее из таблицы
центра не читаются и не сохраняются. Если в таблице есть ошибка (например, неверная дата),
не загружается ничего. Повторная загрузка той же таблицы обновляет записи, а не дублирует их.

Загруженные результаты видны в «Моих результатах» и передаются ИИ-помощнику
вместе с тестами сайта, когда он составляет стратегию.
